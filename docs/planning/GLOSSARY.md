# GLOSSARY — Hospital Crisis

> คำศัพท์ร่วมของโดเมน (ไม่ใช่คู่มือติดตั้งหรือสเปก API); draft ยังไม่ merge เข้า repository.

- **Hospital Crisis:** เกมจำลองการบริหารห้องฉุกเฉินซึ่งผู้เล่นและ AI ร่วมตัดสินใจภายใต้ทรัพยากรจำกัด.
- **Emergency Department (ER):** พื้นที่บริการฉุกเฉินซึ่งเป็นขอบเขตเริ่มต้นของเกม.
- **Wave:** รอบเล่นแบบกำหนดจุดเริ่มและจุดสิ้นสุด ซึ่งมีเหตุการณ์และผู้ป่วยจำลอง.
- **Scenario Archetype:** ประเภทสถานการณ์หลัก เช่น Normal ER, ER Overload, Mass Casualty.
- **Synthetic Patient:** ผู้ป่วยสมมติที่ระบบสร้างขึ้นสำหรับการเล่นและการทดลอง.
- **Game State:** สถานะที่ระบบถือว่าเป็นความจริงของการจำลอง ณ เวลาหนึ่ง.
- **Virtual Clock:** เวลาภายในโลกจำลองที่ไม่ขึ้นกับความเร็วเวลาจริงโดยตรง.
- **Observation:** ข้อมูลบางส่วนของสถานการณ์ที่ AI ได้รับอนุญาตให้มองเห็น.
- **Hidden Ground Truth:** สถานะข้อเท็จจริงที่ใช้ควบคุมสถานการณ์ แต่ยังไม่เปิดเผยแก่ AI.
- **Action:** คำขอให้เกมดำเนินการหนึ่งอย่างผ่านคำสั่งที่กำหนดไว้.
- **Command:** คำสั่งที่มีตัวตนเฉพาะ ผู้สั่ง และการตรวจสถานะก่อนดำเนินการ.
- **Human Override:** การให้ผู้เล่นแทนที่คำเสนอของ AI ที่ยังไม่ถูกดำเนินการโดยยังอยู่ภายใต้ข้อกำหนดเกม.
- **Strategy Plugin:** โมดูลที่เลือกการกระทำจาก Observation โดยไม่ควบคุมความจริงหลักของเกม.
- **Capability:** ความสามารถเสริมด้านการวิเคราะห์ การคาดการณ์ หรือการวางแผนที่ Strategy Plugin เรียกใช้ได้.
- **Capability Registry:** รายการความสามารถของ Plugin ที่ได้รับอนุญาตและพร้อมเรียกใช้.
- **Codex Evolution:** กระบวนการที่ Codex ปรับโค้ด Strategy Plugin หรือสร้าง Capability ใหม่จาก Feedback.
- **Evolution Cycle:** หนึ่งชุดงานสร้าง Candidate ทดสอบ และตัดสินว่าจะนำไปใช้หรือไม่.
- **Candidate:** เวอร์ชันเสนอของ Strategy Plugin ที่ยังไม่ผ่านการยอมรับทั้งหมด.
- **Last Known Good (LKG):** เวอร์ชัน Plugin ล่าสุดที่ผ่านกฎตรวจสอบและถูกยอมรับ.
- **Safe Promotion:** การอนุมัติเวอร์ชัน Candidate หลังผ่านเกณฑ์ที่กำหนดและใช้ได้ตอนเริ่ม Wave ใหม่เท่านั้น.
- **Rollback:** การกลับไปใช้ LKG เมื่อ Candidate หรืองานวิวัฒนาการมีปัญหา.
- **Fitness:** คะแนนคุณภาพเชิงเปรียบเทียบของกลยุทธ์ AI จากเกณฑ์ในเกมจำลอง.
- **Paired Seed:** ค่ากำหนดสถานการณ์เดียวกันสำหรับทดสอบ AI สองเวอร์ชันเพื่อเปรียบเทียบอย่างควบคุม.
- **Development Benchmark:** ชุดสถานการณ์ที่ผู้พัฒนาหรือ Codex ได้รับ Feedback สำหรับปรับปรุง Candidate.
- **Blind Holdout:** ชุดสถานการณ์ประเมินที่ป้องกันไม่ให้ Codex เห็นข้อมูลเฉลยและผลรายกรณี.
- **Regression Guard:** ข้อกำหนดห้ามประสิทธิภาพถดถอยเกินขอบเขตในสถานการณ์ย่อยใด ๆ.
- **Critical Violation:** การละเมิดกฎสำคัญที่ทำให้ Candidate ไม่ผ่าน โดยยึดข้อเท็จจริงและทางเลือกที่ทำได้ในเกม.
- **Feasibility-Aware Safety:** การแยกความผิดพลาดที่ป้องกันได้จากผลเสียซึ่งหลีกเลี่ยงไม่ได้ภายใต้ข้อจำกัดสถานการณ์.
- **Verified Replay:** การเล่นย้อนหลักฐานเหตุการณ์ที่บันทึกจากการทดลองจริง โดยระบุว่าไม่ใช่การทำงานสด.
